# راه‌اندازی برنامه فروشگاه روی سرور فعلی

این راهنما برای سروری نوشته شده که Apache آن از `/var/www/html` به‌عنوان ریشهٔ وب استفاده می‌کند. فایل‌های داخل مخزن `public/` مستقیماً در `/var/www/html/` قرار می‌گیرند؛ کلمهٔ `public` در URL دیده نمی‌شود. کد داخلی و تنظیمات محرمانه خارج از ریشهٔ وب می‌مانند.

## 1. ساختار نهایی سرور

```text
/var/www/
├── html/                         # DocumentRoot فعلی Apache؛ فقط فایل‌های عمومی
│   ├── index.php
│   ├── chat.php
│   ├── product.php
│   ├── cart.php
│   ├── _bootstrap.php
│   ├── .htaccess
│   ├── api/
│   ├── css/
│   └── js/
└── smart-shop-private/           # کد داخلی؛ خارج از DocumentRoot
    ├── app/
    ├── config/
    ├── database/
    ├── prompts/
    └── logs/
```

از پوشهٔ دیگری به نام `/var/www/smart-shop` استفاده نکنید. این طرح مسیر خصوصی جدید `/var/www/smart-shop-private` را در نظر می‌گیرد.

## 2. قواعد استقرار مهم

1. قبل از هر تغییر، از `/var/www/html` نسخهٔ پشتیبان خارج از DocumentRoot تهیه کنید.
2. فقط محتویات `public/` را به `/var/www/html/` کپی کنید؛ خود پوشهٔ `public` نباید بخشی از URL شود.
3. پوشه‌های `app/`، `config/`، `database/`، `prompts/` و `logs/` را در `/var/www/smart-shop-private/` قرار دهید.
4. فایل `public/_bootstrap.php` مسیر `/var/www/smart-shop-private/app/bootstrap.php` را می‌شناسد. در صورت استفاده از مسیر دیگری، متغیر محیطی `SMART_SHOP_PRIVATE_PATH` را برای Apache تنظیم کنید.
5. فایل `index.html` فعلی سایت، در صورت باقی‌ماندن، ممکن است پیش از `index.php` نمایش داده شود. ابتدا آن را با نامی مثل `index.html.backup` به مکانی خارج از DocumentRoot منتقل کنید؛ تنها پس از تأیید نسخهٔ پشتیبان.
6. فایل‌های آزمایشی مثل `test_avalai.php` و API قدیمی `chat_api.php` را به ریشهٔ عمومی منتقل نکنید. اگر نسخه‌ای از آن‌ها هم‌اکنون در وب‌ریشه وجود دارد، قبل از حذف یا جابه‌جایی، محتوای امن آن را بررسی و نسخهٔ پشتیبان را خارج از وب‌ریشه نگه دارید.
7. فایل `.htaccess` موجود سرور را کورکورانه جایگزین نکنید. نسخهٔ داخل `public/` برای استقرار تازه است؛ روی سرور فعلی، قواعد امنیتی موجود را حفظ و تغییرات را با دقت ادغام کنید.

## 3. تنظیمات محرمانه

در مسیر خصوصی، فایل‌های واقعی را از نمونه‌ها بسازید:

- `config/app.example.php` ← `config/app.php`
- `config/ai.example.php` ← `config/ai.php`
- `config/database.example.php` ← `config/database.php`
- `config/secrets.example.php` ← `config/secrets.php`

رمز دیتابیس، کلید API و مقادیر واقعی محرمانه را در Git یا پوشهٔ عمومی قرار ندهید. دسترسی فایل‌های تنظیمات باید محدود باشد و فقط کاربر لازم برای اجرای PHP بتواند آن‌ها را بخواند.

## 4. دیتابیس و دستیار

- پیش از اجرای هر SQL روی دیتابیس موجود، نسخهٔ پشتیبان تهیه کنید و طرح فعلی را با `database/schema.sql` و `database/migrations/001_conversation_tables.sql` مقایسه کنید. این فایل‌ها را بدون بررسی روی دیتابیس تولید اجرا نکنید.
- در `config/ai.php`، حالت نمونه `mock` است. حالت `live` را فقط پس از تنظیم آدرس سرویس، نام مدل و کلید معتبر در فایل خصوصی فعال کنید.
- تنظیمات دیتابیس باید با نام دیتابیس و کاربری که واقعاً روی سرور ساخته شده‌اند مطابقت داشته باشند؛ این راهنما فرض نمی‌کند که نام کاربری یا رمز فعلی از قبل معلوم است.

## 5. بررسی پس از استقرار

1. اجرای `sudo apache2ctl configtest` باید با `Syntax OK` تمام شود.
2. بررسی نحوی فایل‌های PHP را انجام دهید؛ سپس `sudo systemctl reload apache2` فقط در صورت تغییر تنظیمات Apache و بعد از موفقیت configtest اجرا شود.
3. صفحهٔ اصلی، جزئیات محصول، نشست گفتگو، API گفتگو و افزودن به سبد خرید را جداگانه آزمایش کنید.
4. لاگ Apache و لاگ برنامه را برای خطا بررسی کنید.
5. آزمون lint موفق به‌تنهایی به معنی موفقیت اتصال واقعی دیتابیس یا سرویس هوش مصنوعی نیست.

## وضعیت قابلیت‌ها

سبد خرید فعلی در PHP session نگهداری می‌شود و پرداخت آنلاین یا ثبت سفارش نهایی ندارد. این راهنما ساختار استقرار را مستند می‌کند؛ به‌خودی‌خود هیچ فایلی را روی سرور تغییر نمی‌دهد.
